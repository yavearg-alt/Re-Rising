# Re:Rising — SAO Unleash Blading revival

Re:Rising is an open-source, fan-made **private server** for *SAO Unleash Blading* 3.7.0 (Android), whose official
service ended in 2023. It lets you play the game again **on your own PC or phone**, with no connection to any
official or third-party server.

This repository contains:

| Part | Where | What it does |
|---|---|---|
| Local server | `server/` | The game API, asset CDN and GREE login emulation (Python 3.11+, standard library + `msgpack`) |
| Tests | `tests/` | A fake game client that runs scenarios against the server in-process (`python tests/run.py`) |
| APK patcher | `tools/patch_apk.py`, `tools/build_apk.sh` | Points **your** copy of the game at your server |
| Launcher | `SAOUB_Launcher.bat`, `tools/launcher/` | A small Windows window to start/stop the server, back up the database, install the APK into BlueStacks |
| Data tools | `tools/extract_apk.py`, `tools/extract_dump.py`, `tools/dump_masters.py`, `tools/saoub_crypto.py`, `tools/flatmaster.py` | Decode the game's manifests and master data from your own files |
| Docs | `docs/` | Protocol notes and API routes |

> **No game content is included, and none may be added.** *SAO Unleash Blading*, *Sword Art Online* and every game
> file, image, sound, text and data table belong to Bandai Namco Entertainment, Reki Kawahara / KADOKAWA / SAO
> Project. This project is not affiliated with or endorsed by them. You must supply your own copy of the game.

## What you need

- **Python 3.11+** (Windows, Linux or macOS for the server; the APK build scripts are Windows-first).
- **Your own SAO Unleash Blading 3.7.0 APK** (`com.bandainamcoent.saoars`, version code 4728).
- **The downloaded game files** (~4.7 GB) from an installation of the game made while the service was live: the
  `/data/data/com.bandainamcoent.saoars` folder of a device (see `docs/PROTOCOL.md`, "Sample data"). The official
  CDN is gone, so the server can only serve files you have.
- To build APKs: a JDK 21, Android build-tools (`d8`, `zipalign`, `apksigner`), `apktool` 2.9.3 and a platform
  `android.jar` (API 31).

## 1. Set up

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt      # Linux/macOS: .venv/bin/pip
```

Everything is configured with environment variables; `.env.example` lists them all with their defaults.
The important ones:

| Variable | Default | Meaning |
|---|---|---|
| `SAOUB_DATA` | `<repo>/data` | Your data folder (see below) |
| `SAOUB_APK` | `<repo>/SAO+Unleash+Blading_3.7.0_APKPure.apk` | Your original APK |
| `SAOUB_HOST` | `127.0.0.1` | `0.0.0.0` to let a phone on your Wi-Fi connect |
| `SAOUB_PORT` | `8080` | Game server port |
| `SAOUB_ADMIN_PASSWORD` | *(empty = admin panel off)* | Admin panel password (or `server/admin_password.txt`) |
| `SAOUB_TOOLS` | `$SAOUB_DATA/tools` | JDK / Android build-tools / apktool for `tools/build_apk.sh` |

The `data/` folder (gitignored) is laid out like this:

```
data/
  dump/data/data/com.bandainamcoent.saoars/files/contents/   manifest/ and hashed/ from your device dump
  extracted/master_final/      decrypted final master data      (tools/extract_dump.py)
  extracted/master_json/       master tables decoded to JSON    (tools/dump_masters.py)
  extracted/sample_user/       new-account template tables      (from the dump's local user data)
  server_cache/                generated by the server on first start
  tools/                       build toolchain (optional, see above)
```

```bash
python tools/extract_apk.py   <your.apk> data/extracted
python tools/extract_dump.py  <your.apk> data/dump data/extracted
python tools/dump_masters.py  data/extracted/master_final data/extracted/master_json
```

## 2. Run the local server

- **Windows:** double-click `start_local_server.bat`, or `SAOUB_Launcher.bat` for the launcher window.
- **Any OS:** `cd server && python main.py`

The server listens on `http://127.0.0.1:8080` by default. The admin panel (when a password is set) is on
`http://127.0.0.1:8082/saoub-admin/` with `start_local_server.bat` (`8081` when started by hand).

Run the tests (they use a throwaway copy, never your database):

```bash
python tests/run.py            # -k <name> to filter, -v for details
```

## 3. Point the game at your server

```bash
# BlueStacks / Android emulator on this PC (10.0.2.2 = the host PC)
tools/build_apk.sh http://10.0.2.2:8080
# a phone on your Wi-Fi (start the server with SAOUB_HOST=0.0.0.0)
tools/build_apk.sh http://192.168.1.20:8080
```

The patched, debug-signed APK lands in `data/build/saoub_private.apk`. Uninstall the original game first if Android
refuses to install it.

**32-bit and 64-bit.** The APKPure-style single APK only has the 32-bit game (`lib/armeabi-v7a/libapp.so`):
64-bit-only phones and emulators (e.g. MuMu's Android 15 image, `ro.product.cpu.abilist` = `x86_64,arm64-v8a,x86`)
refuse it with `INSTALL_FAILED_NO_MATCHING_ABIS`. The Google Play build of 3.7.0 (4728) also shipped a 64-bit split,
`config.arm64_v8a.apk` (e.g. inside an APKMirror `.apkm` bundle, signed by NAMCO BANDAI Games Inc.). Give it to the
build and the APK gets both versions, Android picking the right one per device:

```bash
ARM64=path/to/bundle.apkm tools/build_apk.sh http://10.0.2.2:8080
```

### 120 fps

`tools/build_apk.sh` includes a frame-rate unlock (`tools/fps_patch.py`): the game stays
at 60 fps until `Android/data/com.bandainamcoent.saoars/files/saoub_fps.txt` holds `90` or `120`. The launcher writes
it to BlueStacks (SETTINGS > Frame rate); `FPS=120 tools/build_apk.sh ...` bakes a default
instead. The screen (or BlueStacks' own frame-rate setting) must go that high too.
